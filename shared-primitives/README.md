# Shared primitives

A shared primitive is a skill, agent, instruction or prompt that ships under the same name, with identical content, in several packs. Every pack installs it into the same user-profile folder, so whichever pack is installed last overwrites the copy with the same files and nothing is lost. A primitive that only shares a name, with different content, is a real install collision; `tooling/check_collisions.py` reports those.

This folder holds the one canonical copy of each shared primitive, laid out like a pack's `.apm/` folder: `skills/`, `agents/`, `instructions/` and `prompts/`. `consumers.json` lists the packs that ship each one.

## Cloud diagrams: AWS, Azure and Google Cloud

| Primitive | What it covers | Shipped by |
|---|---|---|
| skill `drawio-core-generation` | Creating and editing Draw.io diagrams for one provider or several together: generation path, each provider's current icon library, and boundary nesting rules | the AWS, Azure and Google Cloud architect packs, and the AWS and Azure designer packs |
| skill `diagram-validation-and-evidence` | Structural, icon-currency, boundary and evidence checks, with `scripts/check_drawio.py` and its generated draw.io icon catalog | same five packs |
| skill `drawio-render-export-and-review` | Draw.io Desktop export options and rendered review, including how each provider's icons fail visibly | same five packs |

Cloud providers mostly share concepts, so these skills hold one workflow and a reference per provider.

## Programming languages: Python and TypeScript

| Primitive | What it covers | Shipped by |
|---|---|---|
| skill `agent-evaluation` | Scenario datasets, deterministic and judged checks, budgets and reports | the Python and TypeScript Distinguished Engineer packs |
| skill `agentic-workflow-design` | States, tools, memory, budgets, cancellation and handoffs | same two packs |
| skill `playwright-validation` | Browser journeys with Playwright for Python or Playwright Test | same two packs |
| skill `secure-agent-engineering` | Agent threats plus each language's dangerous APIs and supply chain | same two packs |
| agent `agent-evaluation-engineer` | The evaluation specialist both primary agents delegate to | same two packs |
| instruction `agentic-security` | Always-on security rules for `.py`, `.ts` and `.js` files and agent or MCP configuration | same two packs |
| prompts `evaluate-agent`, `validate-web-flow` | The workflows that run the evaluation and Playwright skills | same two packs |

Languages differ in concepts, not just names: runtime typing, concurrency and cancellation, package installation and test tooling all work differently. So each language skill picks the language from the code under change, carries a table of where the two languages differ for that work, and keeps one reference per language. It translates concepts between the languages and never carries one language's code or idioms into the other. Because both languages are in every copy, either pack alone can handle code in either language.

## Changing a shared primitive

1. Edit the copy here, never a pack's copy.
2. Run `python tooling/sync_shared.py`. It copies each primitive into every listed pack and regenerates `tests/skill-coverage.yml` for each pack whose skills changed.
3. Bump the version in each changed pack's `apm.yml`, validate the packs, and open one pull request.

CI runs `python tooling/sync_shared.py --check`, which fails when a copy differs from this folder or when a pack that is not listed ships a primitive with a shared name.

## Keeping the diagram facts current

- `skills/diagram-validation-and-evidence/scripts/icon_catalog.json` is generated by `python tooling/build_icon_catalog.py --tag <draw.io tag>` from draw.io's public source. Do not edit it by hand.
- `diagram-facts.json` ties each provider's current icon release to a marker on its official page.
- The weekly `watch diagram sources` workflow rebuilds the catalog from the newest draw.io release and checks the markers. It opens one issue when either changes, with the steps to adopt the change.
