# Shared skills

A shared skill ships under the same name, with identical content, in several packs. Every pack installs it into the same user-profile skills folder, so whichever pack is installed last overwrites the copy with the same files and nothing is lost. A skill that only shares a name, with different content, is a real install collision; `tooling/check_collisions.py` reports those.

This folder holds the one canonical copy of each shared skill. `consumers.json` lists the packs that ship each one.

| Skill | What it covers | Shipped by |
|---|---|---|
| `drawio-core-generation` | Creating and editing Draw.io diagrams for AWS, Azure, Google Cloud or several together: generation path, each provider's current icon library, and boundary nesting rules | the AWS, Azure and Google Cloud architect packs, and the AWS and Azure designer packs |
| `diagram-validation-and-evidence` | Structural, icon-currency, boundary and evidence checks, with `scripts/check_drawio.py` and its generated draw.io icon catalog | same five packs |
| `drawio-render-export-and-review` | Draw.io Desktop export options and rendered review, including how each provider's icons fail visibly | same five packs |

## Changing a shared skill

1. Edit the folder here, never a pack's copy.
2. Run `python tooling/sync_shared_skills.py`. It copies the folder into every listed pack and regenerates each changed pack's `tests/skill-coverage.yml`.
3. Bump the version in each changed pack's `apm.yml`, validate the packs, and open one pull request.

CI runs `python tooling/sync_shared_skills.py --check`, which fails when a copy differs from this folder or when a pack that is not listed ships a skill with a shared skill's name.

## Keeping the diagram facts current

- `diagram-validation-and-evidence/scripts/icon_catalog.json` is generated by `python tooling/build_icon_catalog.py --tag <draw.io tag>` from draw.io's public source. Do not edit it by hand.
- `diagram-facts.json` ties each provider's current icon release to a marker on its official page.
- The weekly `watch diagram sources` workflow rebuilds the catalog from the newest draw.io release and checks the markers. It opens one issue when either changes, with the steps to adopt the change.
