# Design a Python change

## Inputs

Use the user's current task, authorized repository, acceptance criteria and relevant existing evidence. Discover missing local facts before asking. Do not invent credentials or organizational policy.

## Workflow

Frame goal, scope/non-goals, proposed criteria, assumptions and dependencies. Compare meaningful alternatives and apply architecture-decision-records for durable choices.

## Expected output

Design/ADR, interface/data impact, risk/approval classification, implementation/test plan and rollout/recovery. State failures and unavailable checks honestly. Follow the installed approval and completion contract; existing authorization persists only within its scope.
