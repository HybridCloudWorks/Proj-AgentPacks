# Python change completion report

Use the machine-readable tests/report-contract.yml field names when recording completion evidence. Each acceptance criterion has a status and evidence. Each check records command, exit_code, status and evidence; unavailable checks are unverified rather than passed. Include API/dependency/data/operations/telemetry/performance/cost/compatibility impacts, rollback limits, remaining risks and follow-ups.

COMPLETE_VERIFIED requires at least one criterion, no failed/unverified criterion, recorded passing checks, and no unverified item. Otherwise use the appropriate incomplete/analysis status and the exact fallback sentence when implementation evidence is missing.
