# Purpose and Information Architecture

Start from a reader task or decision, not a document title. State the problem, audience, prerequisites, desired outcome, scope, non-goals, success evidence, owner, review cadence, and expected shelf life.

Choose the smallest useful document set. Separate overview from procedure, reference, decision history, and operational evidence. Use links to connect related pages; avoid copying content that will drift. Identify the canonical source and label generated, mirrored, archived, and deprecated copies.

Design navigation by reader intent and domain vocabulary. Check discoverability, breadcrumbs, stable filenames, redirects, cross-references, and version boundaries. For a proposed reorganization, provide an inventory, mapping, redirect plan, owner, migration sequence, and rollback rather than silently moving pages.
