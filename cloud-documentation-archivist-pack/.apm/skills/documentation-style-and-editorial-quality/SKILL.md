# Style and Editorial Quality

Lead with reader outcome and relevant context. Use plain technical language, short paragraphs, meaningful headings, consistent terms, active voice where natural, and descriptive links. Preserve local voice when editing an existing repository.

Make code examples minimal, complete enough to be useful, syntax-highlighted, copy-safe, and explicit about placeholders. Use uppercase placeholders for values that vary. Label illustrative output and distinguish expected output from a live result.

Check heading hierarchy, alt text, table readability, link text, keyboard-friendly structure, localization concerns, alerts, dates, units, capitalization, and terminology. Remove promotional language, duplicate explanations, stale claims, filler, and unsupported certainty. Do not rewrite a document merely to impose a preferred style.
