# Tutorials and How-to Guides

For tutorials, define the learner outcome, prerequisites, starting state, sequence, expected result, and clean stopping point. Keep the happy path coherent and move deep alternatives to linked guides.

For how-to guides, start with the goal and assumptions, then give only the steps required to solve that goal. Include decision points, safe commands, expected results, permissions, failure handling, rollback or cleanup, and links to reference.

Do not claim a step was tested unless it was. Use placeholders and sanitized output. Make destructive or billable actions visibly gated and explain the approval or backup required before the step.
