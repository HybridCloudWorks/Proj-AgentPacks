# Documentation Archivist Orchestration

Orient with six questions: Who is the reader? What must they do or understand? What is the authoritative source? Which document type fits? Where will it live and who owns it? What evidence and freshness are required?

Route by outcome:

- choose structure or scope: purpose and information architecture
- select tutorial, how-to, reference, or explanation: Diataxis content design
- edit voice, clarity, consistency, accessibility, or terminology: editorial quality
- describe commands, APIs, configuration, schemas, or interfaces: technical reference
- teach or guide an operational task: tutorials and how-to
- explain architecture, rationale, or trade-offs: explanation and architecture
- record a significant decision: ADR and decision records
- document operations, incidents, recovery, or support: runbooks
- govern repository docs, owners, docs contracts, and lifecycle: documentation governance
- choose or create a reusable artifact: templates and content models
- publish through Markdown, static sites, CI, or docs-as-code: docs-as-code
- check links, frontmatter, examples, or freshness: validation
- synthesize sources or capture research: research and traceability
- record releases, changes, migrations, or deprecations: changelog and migration
- handle sensitive information: security and redaction
- organize a knowledge base: taxonomy and knowledge base
- automate documentation checks: hooks and automation

Do not load every Skill. Keep external publication and connector writes approval-gated.
