# Technical Reference

Organize reference by the structure of the product: command, endpoint, resource, property, parameter, return value, error, version, and example. Keep reference neutral and complete; link to task-oriented guides for procedures.

For each item record syntax, type, requiredness, default, allowed values, constraints, side effects, permissions, errors, idempotency, version or availability, and a minimal example. Generate from a source schema when reliable, then review generated output for omissions and misleading defaults.

Never invent an API field, response, SKU, limit, or behavior. Mark uncertain or environment-dependent facts and provide the source version/date. Treat live discovery and generated docs as evidence that can expire.
