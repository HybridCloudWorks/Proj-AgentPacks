# Documentation Governance

Inventory document roots, templates, generated outputs, navigation, owners, review metadata, links, automation, and external mirrors. Identify which files are authoritative, generated, archival, or prohibited from editing.

Define a lightweight documentation contract: naming, location, frontmatter, required sections, owner, reviewer, last-reviewed date, status, version, deprecation, and link policy. Match existing project conventions before introducing new folders or root files.

When changing structure, update references, navigation, CI checks, redirects, templates, contributor guidance, and automation together. Do not declare documentation current merely because it was edited; compare it with the implementation or authoritative source.
