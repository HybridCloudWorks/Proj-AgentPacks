# Azure Resilience, DR, and Migration

Translate business continuity targets into failure domains, dependency maps, recovery tiers, and tested runbooks. Distinguish availability zones, paired regions, multi-region active/active or active/passive, backup/restore, replication, and rebuild-from-IaC.

Evaluate Azure Backup, Site Recovery, storage redundancy, database replication, Front Door/Traffic Manager, DNS, queues, and application failover. Include identity, DNS, secrets, keys, observability, quotas, network paths, operator access, and data consistency in the recovery plan.

For migration, inventory and classify workloads, dependencies, data, licensing, connectivity, identity, cutover, rollback, validation, and decommissioning. Require rehearsal and evidence for RTO/RPO; a diagram or plan is not a recovery test. Protect stateful resources from accidental replacement and record irreversible steps in ADRs.
